# Bread Circuit — Design Document

**Date:** 2026-09-02
**Status:** Draft for review
**Origin:** Investigation into native silkscreen-font support in tscircuit; escalated into a full single-package fork decision.

---

## 1. Goal

Build **one npm package** (`bread-circuit`, name TBD) that compiles Bread Modular
TSX circuit modules into fabrication-ready outputs — with **no npm dependencies
except the React stack** — replacing the 192-package / 27MB `tscircuit` CLI
toolchain we use today.

- Runs on **Bun or Node** (no bun-only APIs in core paths).
- KiCad-accurate silkscreen text is a **native feature**, not a node_modules patch.
- Autorouter (capacity-autorouter) and simulation (ngspice) are **kept, as-is**.
- Maintained by our own agents; **no upstream support required**.

## 2. Scope — what the package must do

Derived exactly from what `ts-modules/build.sh` uses today:

| Feature | Replaces |
|---|---|
| TSX → circuit-json (`build`) | `tsci build` |
| DRC checks | `@tscircuit/checks` path |
| Schematic SVG export | `tsci export -f schematic-svg` |
| PCB SVG export | `tsci export -f pcb-svg` |
| Assembly SVG export | `tsci export -f assembly-svg` |
| JLCPCB package: gerbers + drill + zip | `tsci export -f gerbers` |
| BOM + pick-and-place CSV | extracted from zip today |

## 3. Non-goals

- 3D rendering (gltf/jscad/three), enclosures, image pipeline
- Web UI (runframe/eval webworker/CDN loading)
- KiCad import, matchpack, schematic "smart" auto-layout solvers
- Browser in-browser editor; this is a build tool
- API compatibility with `tscircuit` npm package

## 4. Strategy: source-lift (not vendoring, not forking)

We **do not vendor** node_modules and we **do not clone upstream repos**.
Instead: read upstream source, **lift only the code the pipeline needs** into
our own `src/` tree, adapted to our structure and naming. The result reads as
one coherent first-party codebase.

| Treatment | Packages |
|---|---|
| **Lift near-verbatim** (small, stable) | `circuit-json` (schema), `props`, `alphabet`, `checks`, `footprinter`, `schematic-symbols`, `circuit-json-util`, `soup-util`, `math-utils`, `mm` |
| **Lift + modify** | `core` (fiber/layout — drop unused layout paths), `circuit-to-svg` (svg subset only), `circuit-json-to-gerber`, `pnp-csv` writer |
| **Lift as-is (heavy, keep working)** | `capacity-autorouter` + its 0-dep solver chain (`infgrid-ijump-astar`, `solver-utils`, `math-utils`, `calculate-*`), ngspice glue + WASM asset |
| **Write fresh** | CLI, font registry, KiCad font data, stroke-text SVG renderer, ngspice worker adapter, zip assembly |

Rules for lifting:
1. **Lift whole algorithm files** for math-heavy code — never partially extract math.
2. Strip package scaffolding: no upstream build config, tests optional, no CI files.
3. Keep a `PROVENANCE.md` mapping each lifted file → upstream repo/commit for future reference.

## 5. Architecture

```
bread-circuit/
├── package.json              # deps: react, react-dom, react-reconciler, scheduler ONLY
├── src/
│   ├── cli/                  # ~5 commands (new code)
│   ├── font/                 # NEW: font registry + kicad_sans + tscircuit2024
│   ├── core/                 # lifted: fiber, primitives, layout
│   ├── schema/               # lifted: circuit-json (font: string, not literal)
│   ├── render-svg/           # lifted: pcb-svg + schematic-svg + assembly
│   ├── gerber/               # lifted: gerber/drill/excellon writer + BOM/CPL
│   ├── checks/               # lifted: DRC
│   ├── autorouter/           # lifted: capacity-autorouter + solver chain
│   ├── simulate/             # lifted: eecircuit-engine glue + ngspice.wasm asset
│   ├── geometry/             # hand-rolled minimal 2D math (see §7)
│   └── util/                 # uuid → crypto.randomUUID, stringify, etc.
└── PROVENANCE.md             # where each lifted file came from
```

## 6. Native silkscreen font support (the originating requirement)

Current upstream state: `font` exists end-to-end but is locked to a single
literal (`"tscircuit2024"`); previews render silkscreen text as SVG `<text>`
with Arial (alphabet unused), gerbers use a single global stroke alphabet, and
the web UI loads the font from a CDN — which is why our KiCad-font patch only
works for gerbers.

Design:
- **Font registry** in `src/font/`: `{ tscircuit2024, kicad_sans }`, each font
  carries `{ lineAlphabet, svgAlphabet, glyphAdvanceRatio, strokeWidthRatio,
  baseline metrics }`.
- **circuit-json schema**: `font: z.string().default("tscircuit2024")`
  (upstream uses `z.literal`).
- **Gerber writer**: dispatch on `elm.font`; aperture width = per-font
  `strokeWidthRatio` (natively replaces our 0.15/0.2 bold-stroke patch).
- **SVG previews render stroke text** (same path geometry as gerbers) →
  preview == gerber, pixel-perfect; no Arial approximation ever.
- **Baseline metrics per font** natively fix the bottom-anchor ink shift we
  currently patch for.
- KiCad glyphs generated by `scripts/kicad-font/extract-glyphs.py` (already in
  the normalized 1×1 format) feed `fonts/kicad_sans`.
- Deletes `scripts/kicad-font/apply-kicad-font-patch.mjs` and the postinstall hook.

## 7. Native built-ins instead of deep-math libs

| Upstream dep | Replacement |
|---|---|
| `fflate` (zip) | Node/Bun builtin `zlib` (deflate-raw) + ~150-line ZIP container writer (JLCPCB-verified format) |
| `nanoid` | `crypto.randomUUID()` |
| `fast-json-stable-stringify` | ~20-line sorted-key stringify |
| `object-hash`, `stack-svgs` | Drop / stub (debug-only) |
| `svg-path-commander`, `transformation-matrix` | Hand-rolled minimal 2D affine + path transform subset (~150–300 lines) |
| `@flatten-js/core` | **Audit call sites first.** Likely only rect/circle analytic geometry needed for our footprints; replace with targeted code, drop boolean ops if nothing requires them |
| `@lume/kiwi` (Cassowary) | **Audit call sites.** If only used for schematic auto-layout, replace with explicit placement (Bread modules are hand-laid) or a minimal greedy pass |

Audit rule: no OS builtin exists for boolean geometry or constraint solving —
so the goal there is **elimination via usage audit**, not reimplementing the
full library.

## 8. Runtime & toolchain

- **Targets Bun and Node** — standard APIs only: `fs`, `path`, `URL`,
  `WebAssembly`, `zlib`, `crypto`.
- Bun preferred for dev (runs TSX directly, fast installs); Node compatibility
  verified in CI-equivalent test script.
- TSX transpile: bun-native in dev; for Node, either bun-built JS output or a
  tiny sucrase lift (decide in Phase 1).
- ngspice WASM shipped as a package asset; **loaded locally** — kills the
  `jscdn.tscircuit.com` CDN dependency. Worker adapter written for bun/node
  (upstream glue is browser-worker flavored).

## 9. Phased plan (agent tasks)

**Phase 0 — Spikes (1–2 days each, parallel)**
- [ ] Zip: generate a JLCPCB-accepted zip with builtin zlib + container writer
- [ ] Ngspice worker adapter: run eecircuit-engine glue under Bun and Node
- [ ] Audit `flatten-js` + `kiwi` call sites in lifted `core` → keep/replace/kill list

**Phase 1 — Gerbers + PCB SVG with native font**
- Lift `circuit-json`, `alphabet` (build registry), gerber writer, pcb-svg path
- Wire KiCad font natively; **exit criteria:** `build.sh` outputs identical
  gerbers to today (patched toolchain) with zero node_modules patches

**Phase 2 — Full build parity**
- Schematic SVG, assembly SVG, DRC, BOM/CPL, zip assembly
- **Exit criteria:** new CLI reproduces every artifact `build.sh` produces today

**Phase 3 — Ownership & polish**
- Custom CLI (`bm build`, ~5 subcommands), drop `tsci`
- Autorouter + simulation wired via dynamic import (zero cost when unused)
- Delete patch script; update `ts-modules` build scripts; docs

## 10. Risks & open questions

1. **`core`'s internal bundling** — footprinter/props/schematic-symbols may be
   baked into its dist; verify true import graph when lifting source.
2. **Schematic rendering** may pull layout solvers (`schematic-match-adapt`,
   `schematic-trace-solver`) — decide lift-vs-kill in Phase 0 audit.
3. **Ngspice glue** may need node/bun worker shim (comlink upstream).
4. **Parity testing**: keep current patched `tscircuit` installed until Phase 2
   exit criteria pass; diff gerbers byte-wise (font geometry) per module.
5. Upstream drift is accepted permanently — `PROVENANCE.md` is the safety net.

## 11. Upstream references (investigated 2026-09-02)

- `tscircuit/alphabet` — single hardcoded stroke font, 1×1 normalized glyphs,
  `strokeWidthRatio = 0.09` (we patch to 0.15/0.2)
- `circuit-json` `PcbSilkscreenText.font: z.literal("tscircuit2024")`
- `circuit-to-svg` — non-knockout silkscreen text → SVG `<text font-family="Arial">`;
  knockout text uses alphabet strokes
- `circuit-json-to-gerber` — `getAlphabetLayout()` + aperture = fontSize × strokeWidthRatio
- `runframe` loads `@tscircuit/eval` from jsdelivr CDN → unpatchable web UI
- `@tscircuit/ngspice-spice-engine` is a thin loader → imports
  `@tscircuit/eecircuit-engine` from tscircuit CDN (1.7.6)
- `@tscircuit/core` deps: 12 ordinary deps, **zero @tscircuit packages** — lifts cleanly
- `capacity-autorouter` chain: all pure TS, trivial deps only
