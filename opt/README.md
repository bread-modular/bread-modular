# KiCad footprint libraries

`fp-lib-table` is the single project-specific footprint library table for all
Bread Modular KiCad projects, including deprecated modules and breakout boards.
Edit it here, not separately in each project. Existing library nicknames are
preserved, including the historical `BreadModular_Panalize` spelling and the
RP2350 breakout's `RP2350_60QFN_minimal` library.

Each project directory contains two **relative symlinks**:

- `fp-lib-table` → this shared `opt/fp-lib-table` file.
- `footprints` → `opt/footprints`, a directory of symlinks to the actual libraries.

The table uses `${KIPRJMOD}/footprints/<library>.pretty`. The `footprints` link
makes this work at any project depth without hard-coded checkout paths or
machine-wide KiCad environment variables. Linking to the library-only directory
also avoids directory cycles through the projects under `opt/Breakouts`.
Standard KiCad libraries continue to come from KiCad's global library table.
Custom symbol-library configuration is unchanged.

## Workspace setup

`workspace_init.sh /path/to/original/checkout` copies **all** submodules listed in
`.gitmodules`, including the four footprint-library submodules and the firmware
library. Tracked libraries and symlinks already arrive with the Git worktree.

- Setup never clones, fetches, or falls back to the network.
- Each copy includes private Git metadata and objects; no hardlinks or Git links
  back to the original checkout are used. Local source changes are copied too.
- Rerunning setup leaves initialized destinations (and their edits) untouched.
- Missing source checkouts or nonempty uninitialized destinations fail with an
  actionable error rather than fetching or overwriting files.
- Sources must be ordinary initialized submodules, not linked worktrees or
  repositories borrowing objects via Git alternates.

On a fresh main checkout, explicitly initialize submodules once before creating
workspaces: `git submodule update --init --recursive`. This manual bootstrap may
access the network; workspace creation itself does not.

## Adding a project

Create both symlinks next to its `.kicad_pro` file, adjusting the relative paths
for its depth. For example, from the repository root:

```sh
ln -s ../../opt/fp-lib-table modules/new-module/fp-lib-table
ln -s ../../opt/footprints modules/new-module/footprints
```

To add a library, add its symlink under `opt/footprints` and its entry to
`opt/fp-lib-table`. Existing projects immediately share the new entry. Reopen
KiCad if it has cached the old library table.

## Verification

From the repository root, with local submodules initialized:

```sh
python3 tests/test_workspace_init.py
# Optional: test copying the original checkout's .git-file-based submodules.
python3 tests/test_workspace_init.py /path/to/original/checkout

# Use a Python interpreter with KiCad's pcbnew module installed.
/usr/bin/python3 tests/check_kicad_libraries.py --drc
```

The workspace tests forbid Git transports and check independent copies,
relocation, rerun safety, and failure cases. The KiCad check verifies every
project link and custom footprint reference, loads the library footprints with
KiCad, and optionally checks every board for missing/unloadable shared libraries
via `kicad-cli`. Global-library footprint issues are reported separately; they
and unrelated existing PCB design-rule violations do not fail the shared-library
check. Projects without a PCB or generated by a newer KiCad major version than
the installed CLI are explicitly skipped for board DRC; their shared-library
paths and footprint loads are still checked.
